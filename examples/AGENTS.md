## Project and authority

Describe the product, current goals and canonical plan/spec/test locations here.

## Workflow routing

- Use git-contractmaxxer for GitHub-based feature planning/delivery or takeover.
- Use product-board for related outcomes and the existing shared roadmap.
- Use contractmaxxer only where the project adopts its contract/UVP pipeline.
- Use fleet-controller before delegation; select an available authorized model
  and effort, then the adapter. A single bounded task does not need a swarm.
- Use disk-janitor when storage pressure requires it; keep cleanup within actual
  ownership and deletion authority.
- The core recommendation includes just-say-no-to-process-porn-and-ceremony from
  its authorized upstream. Use it for relevant ceremony/evidence checks when
  available; report missing access honestly without blocking unrelated work.
- Load optional reality-check-for-project only if installed from its authorized upstream.
- Use task-specific browser, design or deployment skills when they apply.
  Missing optional helpers block only the operations that consume them.

## Delivery and proof

Work toward the authorized useful outcome. Reuse existing issues, ownership,
plans and evidence instead of building a duplicate tracker. Verify the real
consumer, run relevant checks, and distinguish local, pushed, merged and deployed.
If contrary evidence changes the plan, reconcile only affected work. Do not add
checks or process artifacts without a concrete decision or observed defect.
Preserve healthy in-flight work, source identity and checkpoints at handoff.

## Permissions — fill in your own policy

Specify who can push, open/merge PRs, change issue state, deploy, spend money,
message others and touch production data. Record any standing approval with its
source and scope. A template grants no permission. Keep machine/account details,
private model registries and runbooks outside public agent instructions.

## Commands — replace these placeholders

exists. Use it for private machine/checkout facts, not changes to team requirements
